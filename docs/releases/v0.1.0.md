# KRNL0 server 0.1.0

The first version. Run KRNL0 on a computer at home, and your board is on every computer you connect and on your phone.

**Step by step, with pictures:** [theminddev.com/krnl0/server.html](https://theminddev.com/krnl0/server.html)

## What it does

- **App sync.** The KRNL0 app (0.13 or newer) on several computers shares one board. Offline is fine: changes wait and go when the server is back.
- **Website.** Log in from any browser and your board is there, laid out for a phone, an iPad or a computer.
- Choose one or both in `krnl0 setup`.

## Install

**Docker** (a NAS, a home server, Docker Desktop):

```sh
docker run -d --name krnl0 --restart unless-stopped \
  -p 8443:8443 -v krnl0-data:/data \
  -e KRNL0_HOSTS=192.168.1.20 -e TZ=Europe/Berlin \
  ghcr.io/theminddeveloper/krnl0-server:0.1.0
docker logs krnl0
```

Open the address from the log, continue past the browser's warning once, type the setup code and choose a password. Compose: `compose.yml` and `env.example` below.

**Linux, one command** (Raspberry Pi OS, Ubuntu, Debian, 64-bit):

```sh
curl -fsSL https://github.com/theMindDeveloper/krnl0-server/releases/latest/download/install.sh | sh
```

It checks the download, installs a locked-down service and asks you four questions in the terminal. Run it again to update.

Then, in the KRNL0 app: click **saved** in the top bar, **Connect server**, and compare the fingerprint with `krnl0 fingerprint`.

## Safe by default

- Every connection is HTTPS. The server makes its own certificate; the app pins its fingerprint. Your own domain, Tailscale or your proxy work too.
- Passwords with Argon2id, optional two-factor codes, login limits, revocable devices and sessions.
- The container runs as a non-root user on a read-only file system; the Linux service is sandboxed by systemd.
- Daily backups, and one before every new version. No telemetry: the only outgoing request is a daily update check, which you can switch off.

## Check the download

`SHA256SUMS` lists every file; it is signed with Sigstore (`SHA256SUMS.sigstore.json`), and so is the Docker image. The image carries an SBOM and build provenance.

```sh
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity-regexp '^https://github.com/theMindDeveloper/krnl0-server/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
```
